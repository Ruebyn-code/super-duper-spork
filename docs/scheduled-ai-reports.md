# Scheduled AI reports

Open **Reporting → AI reports → Schedules → New schedule**. Name the report, describe the questions you want answered, and choose topics: Business performance, Sales, Supplier orders, Stock usage, Training, Checklists and Location rankings. Choose up to ten locations in the current company, a reporting period, and a daily, weekly or monthly schedule. All times use **Australia/Melbourne**, including daylight saving. A monthly day beyond the end of a short month uses that month's final day. Repeated daylight-saving times use the later occurrence; a skipped time moves to the first valid minute.

Select individual users, permission levels, or both. These combine as a union: someone selected twice receives one report. Permission-level membership resolves again for each run. A recipient needs Reporting access to all selected locations, Training reporting access for training topics and checklist viewing/audience access for checklist topics. Someone who lacks access is excluded, rather than receiving a broader report. Users without an email address keep their inbox copy; the delivery results show the missing email. Pending invitation accounts are excluded. Each run supports up to 200 eligible recipients. A user's access is checked again for email delivery and every inbox read.

**Preview report** spends one company AI request to create a preview from current saved records. It sends no email, creates no inbox delivery and changes no sales, orders, checklists, training or progress. Review the figures and commentary before enabling a schedule. Saving itself makes no AI or email request. Check **Enable this schedule** and save to start at the next scheduled time. There is no manual Send action. Paused schedules can be prepared before configuration is ready.

Enable company AI under **Settings → AI assistance**. The report sender uses the existing **Sending** settings of the selected email sending location: save its sender address and Resend API key and enable automatic email sending there. The location must be one of the report locations. No new key is exposed to the browser and report email does not use the shared Opstack account-invitation sender. Each recipient receives an individual email, with no other recipient addresses included. Scheduled email requests are paced to stay below two requests per second. “Sent” means accepted by Resend, not confirmed delivery to a mailbox. See the per-recipient results in the report inbox for failed, missing-email, configuration and unconfirmed outcomes.

**Scheduled AI reports** (`reports.manage`) plus Reporting access controls previewing and schedule management. Head Office and Franchisee defaults receive this permission; customised permission levels retain their existing grants. Reporting users can read their own eligible inbox reports. Company report managers can review eligible company schedules and run outcomes. Training/checklist source permissions still apply. Scheduling from a paired kiosk or Opstack support identity is disabled; use a normal user account. Editing a schedule makes the editor its current owner. The owner must retain report management and source access. Pausing, changing, deleting a schedule or suspending its network cancels subsequent delivery checks for an in-flight run.

AI receives the selected topics, report instructions, company/location names and bounded aggregate figures, using the company's existing fixed-model OpenAI integration and estimated monthly budget/request cap. It receives no recipient email addresses, staff names, quiz questions/keys, checklist answers, files, credentials or arbitrary record lookup capability. Training totals deduplicate shared staff assignments; per-location totals retain their own denominators. Checklist totals retain planner audiences and the normal limitations on reconstructing historic unstarted work. Financial figures use the existing saved-week calculation and full weeks ending in the chosen period. Daily sales and order costs retain their exact selected-date sources and Sunday cost allocation. Unknown values remain unknown. Incomplete financial results are not ranked. Stock/supplier detail is bounded to the first ten entries in the normal report order.

AI writes commentary and suggested follow-up with validated references to server-calculated facts. Exact figures are rendered from those facts, separately from the commentary; all source figures and notes remain available in the inbox report. AI interpretation can still be wrong. The source notes explain the dates, missing data and calculation limits. Report generation never publishes training, starts work, records completions, creates orders, updates finances or changes the source data.

The running Node service checks enabled schedules approximately every minute, including active networks that have no user currently signed in. It needs the normal persistent data volume and a single running app instance, as does the rest of this file-backed app. Keep the service awake for punctual reports. After downtime it generates only the latest due occurrence, rather than sending a backlog. Schedule edits calculate a fresh future run. Preview and scheduled generation share the existing company AI quota and conservative usage reservations.

Run claims and per-recipient email state are saved before provider calls. Concurrent scheduler ticks coalesce, and deterministic run IDs and Resend idempotency keys prevent ordinary duplicate delivery. Interrupted or uncertain paid generations are not automatically retried; the next regular run continues. Confirmed generated reports can resume pending deliveries after restart, but an interrupted in-flight email is marked unconfirmed and is not automatically resent. Provider rejections or connection failures retain their recorded status and do not cause a retry loop. Network suspension, migration mode and server shutdown stop new scheduled checks.

Back up **scheduled-ai-reports.json** with the normal private server data. It holds schedule definitions, bounded source snapshots, generated reports and recipient delivery status, with mode 0600. The latest 200 completed/failed/interrupted runs per company are retained; the inbox displays up to 100 accessible runs. In-flight runs are retained. Deleting a schedule preserves eligible previously delivered reports until retention removes them. Automated checks use isolated data, simulated OpenAI/Resend responses and no real keys or paid sends. Validate a real scheduled run after configuring the deployed app.
