# Order history

Open **Ordering → Order history**, or use the Order history link above the catalogue. History shows saved orders for the selected location, including orders recorded by other staff there. Search by stock item, supplier, reference or order ID; filter by supplier and original date. Details retain the item names, units and prices saved with each order. Sending states describe submission to a service or a platform handoff, rather than confirmed supplier receipt.

**Record past order** is available to users with `orders.place`; browsing requires `orders.view`. Choose the original order date, existing stock items, quantities and the actual unit/pack prices. Add an optional order/invoice reference and notes, check the displayed total, then choose **Save to history**. Blank prices remain pending; zero is a known zero price. The original quantities may differ from today's minimum order rules. Record each stock item once per order.

A manual entry represents an order already placed outside OpStack. It sends no supplier email, SMS or platform request, and does not alter the catalogue, stock count snapshots or the current cart. It enters the normal cost, budget and stock-usage calculations on its original Melbourne date. Existing Sunday rules still apply: quantities belong to that Sunday's usage week, while order costs fund the next financial week. The separately saved recording time and staff identity identify when the missing order was entered.

Past order details cannot be edited. A save retry reuses its UUID and canonical details, so concurrent retries create one record. Reusing a request UUID for different details, a normal order or another staff member is rejected. If a network failure leaves the save uncertain, the form retains its request and freezes the entered details for an explicit retry; closing it refreshes history so the user can check for the saved order.

To remove an order, open **View order → Delete order**, review the warning, then confirm **Delete order**. This is available with `orders.place` for both manually recorded and platform orders in the selected location. Cancel or Escape leaves the order untouched. Deleting removes the order from history, search, cost/budget reports and stock-usage calculations; it does not change count snapshots, catalogue prices or the current cart. It does not cancel a supplier order or recall an email: contact the supplier separately if cancellation is needed. Orders still being sent must finish sending before deletion.

Deletion retains a private record with `status: deleted`, `deletedAt`, `deletedById` and `deletedBy` so concurrent requests or a lost-response retry cannot recreate or resend the order. Repeated authorised deletes succeed without changing the original audit. Deleted UUIDs remain reserved; attempting to record or place the same UUID again is rejected. The shared order reader excludes deleted records, including after its cache has been warmed. These private records and audit fields are unavailable through history or the older order-detail endpoint.

The APIs are `GET/POST /api/order-history` and `GET/DELETE /api/order-history/:id`. Delete requests include the displayed `companyId` and `locationId`. Lists return 25 records per page, location/company-scoped summaries and the current `canRecord`/`canDelete` capabilities. Detail responses omit phone numbers, provider configuration, handoff data, internal owner identifiers and request fingerprints. The older `/api/orders/:id` endpoint keeps its owner-only policy. All writes require current order permissions, CSRF and an exact company/location match. Mandatory Comms reading and the persistent navigation shell apply to the page.

Records use the existing UUID order files with `status: requested`, `source: manual_history`, `orderDate`, an original-date `createdAt`, and separate `recordedAt`/`recordedBy` attribution. Item identities and supplier names are resolved from the selected company's catalogue on the server. Prices are submitted as exact integer cents. Native readers therefore include historical entries once without additional report stores or recalculation writes.
