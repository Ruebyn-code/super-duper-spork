# OpStack intelligence

Open **Settings → OpStack intelligence** in the intended company. Head Office has access by default; custom roles can be granted **OpStack intelligence settings** without gaining course or checklist authoring permissions. Each company keeps its own key and usage limits, including when hosted inside an Opstack network.

Add an OpenAI API key with access to **GPT-4.1 mini**, choose an estimated monthly budget in **USD** and a maximum number of intelligence requests, enable drafting, and save. The default budget is US$10 and the default request limit is 100. Saving settings makes no provider request. A blank key field keeps the saved key; disable AI and select Remove to delete it. Keys are saved only in private server data files with mode 0600, and are never included in API responses or browser storage. Protect server data and backups as credentials.

**OpStack intelligence** is available to the corresponding checklist/course authors, both beside the create control and inside each builder. Enter requirements and optionally paste approved reference notes. Generating sends only the selected text and the fixed output instructions to OpenAI's chat completions endpoint, using the pinned `gpt-4.1-mini-2025-04-14` model and structured JSON output. It does not upload files, call tools, activate schedules, start checklists, publish courses or assign training. OpenAI receives the text explicitly submitted by the author; account-level provider retention policies still apply. The request uses `store: false`.

**Comms and Knowledge Library writing:** use **OpStack intelligence** in a post, private chat or article editor. Choose Draft new content, Improve existing text or Summarise source text, then describe the task. The visible approved-source field starts with the current title and written content; review or clear it before generating. Only the instructions and this text are submitted, never conversation history, attached files, media or embedded-video URLs. Writing supports up to 24,000 source characters. It shares the company key, estimated budget and request cap.

Generation shows an editable preview and creates no post, message or article. **Use in editor** adds the reviewed text below the original content by default, or explicitly replaces written content while retaining attached media. Adding below preserves existing formatting; replacing removes written formatting. The editor's Undo restores the previous body. The ordinary Send, Publish or Save action is still required. The original audience, category, article type and required-reading choice stay under the author's control. Chat drafting requires `comms.view` and `comms.chat`; posts and articles require their existing view and company/network publishing permissions. Read-only Library access does not grant writing. Disabled intelligence and exhausted budgets prevent generation without blocking ordinary editing.

**OpStack intelligence planners** in the checklist **Planner** stage suggests up to twelve paused planners for an existing checklist. Checklist drafting can also include planners when scheduling is requested. Ask for multiple schedules for the same checklist, or “make this checklist repeat hourly”. Hourly uses a separate occurrence every hour within its window, so a planner per clock hour is unnecessary. Suggestions support fixed times or opening/closing offsets resolved against each location’s saved trading hours. Only the submitted requirements/reference notes and current Melbourne date go to the provider; saved hours, location/role/user IDs and checklist records are not sent. Generate and Cancel create no planners. Explicit **Add paused planners** or **Open draft in builder** saves paused planners through normal APIs for the current location, with stable retry IDs. Review dates, timing, Locations and Assignees before activation; existing planners and checklist runs remain unchanged. This uses the same company key, budget, request cap, author permissions and CSRF checks as checklist drafting. See [Ops management](ops-management.md#use-location-trading-hours).

**OpStack intelligence questions** in the training course toolbar (also in **Add a block → Knowledge checks**) generates questions from selected written course content, selected **Knowledge Library** articles, or pasted text. Choose any of the nine native question types: Multiple choice, Multiple answers, True / false, Dropdown, Short answer, Fill in the blanks, Number, Matching and Put in order. The default selects every type when the course has room; the count must include at least one of each selected type. Generate up to 20 questions at a time within the course limit of 50. Review the selected source text before generating and review the answers afterward. **Add questions to course** inserts them at the selected section/block position as editable draft questions, preserving existing content and questions. Normal autosave applies; existing published versions and assignments do not change. Closing the popup adds nothing.

Only the explicitly selected written source and optional instructions go to OpenAI. Existing quiz questions/answer keys and files, images, audio, video and embedded media are excluded from source extraction. Library access requires the normal Knowledge Library viewing permission. The server resolves up to ten selected articles against current access and exact revisions before reserving usage; changed articles must be refreshed and selected again. Course or pasted sources have a total 60,000-character limit, including source titles, as do Library selections. Library selection uses article text without importing the articles into the course.

The preview is read-only. **Open draft in builder** creates a normal editable draft after flushing existing valid builder changes; normal autosaving, publishing, planner and assignment permissions still apply. Closing the preview creates no app content. Course sections, lessons, quiz choices and correct answers, and checklist response types are validated with the normal app models. Review generated facts, procedures and quiz answers before publishing or scheduling.

Limits reset at the start of the month in Melbourne time. Before a request, the app atomically reserves an estimate based on a conservative UTF-8 input bound (including schema overhead) and a maximum of 10,000 output tokens (1,000 for search interpretation). Concurrent requests cannot spend the same remaining estimate. Confirmed token usage replaces the reservation; failed requests without confirmed usage keep the reservation and every attempted provider request counts toward the request limit. No automatic provider retry is made. Request IDs coalesce concurrent retries and return the same recently cached result without charging again; older or uncertain results require an explicit new request. In-flight requests settle against their original month and preserve later settings changes. The last 12 results are cached privately; usage references are kept for roughly three months.

Budget estimates default to US$0.40 per million input tokens and US$1.60 per million output tokens. Verify current pricing against the OpenAI account and update the rates in **Cost estimates and billing** if needed. The app cannot know taxes, exchange rates, negotiated prices or other use of the same OpenAI account. These are company app limits based on configured estimates, not a guarantee of the provider's final bill. Configure OpenAI billing controls as appropriate. ChatGPT subscriptions do not include API charges.

Tests use a fake provider and isolated data; they do not make paid requests. A real-key generation must be checked after configuring the deployed app. No environment API key is automatically consumed or shared between companies.

[Scheduled OpStack intelligence reports](scheduled-ai-reports.md) use the same company model, key, estimated budget and request cap. Their selected reporting topics provide bounded server-calculated aggregate facts; recipients and schedules are managed separately in Reporting → OpStack intelligence reports. Previewing spends an AI request but sends nothing. Only enabled schedules create email and inbox deliveries.

## Platform search

The shared search bar uses the OpStack intelligence gradient and supports natural-language searches. Type a request, then press the inline **search arrow** or **Enter** without selecting a result. For example, “where can I see who completed training?” can find Training progress reports for users who have the required reporting permissions. Typing still returns ordinary search matches without making a paid request. Use the arrow keys and Enter to open a selected match. On phones, open the search icon beside the account menu.

Intelligence uses the selected company’s existing key, model, estimated budget and shared monthly request cap. Authoring and settings permissions remain separate: signed-in users can search the pages and records they can normally access. The request sends only the typed search and a static list of permitted page names/descriptions to OpenAI. Searchable records, conversations, articles, staff identities and financial data are not sent for interpretation. The model supplies up to three keyword searches and five permitted page IDs; it supplies no answers or destination URLs. The server searches current records locally and returns actual access-checked matches. Library retrieval examines full article text, heading sections, nested instructions, tables, accordions, image captions, gallery filenames and video captions. A matching section can show its actual saved text, image thumbnail and video availability. This does not transcribe videos, recognise objects in images or invent missing media. A clear submitted match opens automatically; similar matches remain a choice. Article links jump to and highlight the matching section, with its original images and playable videos. Old links re-resolve against the latest readable article. Video playback remains explicit, including embedded YouTube/Vimeo players. An interpreted query is a way to find information, not an answer to a business or policy question.

After generation, the server rechecks identity, location/company scope, required reading and company enablement before retrieving records. Retrying a recently cached interpretation reads current accessible records rather than caching search results. Invalid output and uncertain provider failures retain the normal conservative accounting. Search never creates operational work or acknowledges reading. If intelligence is unavailable or its usage limit has been reached, ordinary search remains available.

## Intelligence appearance

Settings → OpStack intelligence includes five company colour presets: the existing OpStack default, Electric blue, Midnight violet, Blue violet and Ocean. A tint-depth slider runs from 100% (the existing tint) to 160% (deeper). Changes preview locally; the existing Save settings button commits them with the other settings. Colours and tint apply to shared search, intelligence buttons, menus, builders and scheduled report email headers. Saving or previewing appearance makes no AI request and works while intelligence is disabled.

Intelligence uses the self-hosted Space Grotesk variable font, with a system sans-serif fallback; other app typography stays separate. Its SIL Open Font License is included with the font in `public/fonts`. Email clients use their supported sans-serif fallback. Palettes retain the shared four-second shimmer, theme-aware text contrast and reduced-motion support. Intelligence menus, panels and enabled controls have a matching glow on hover, press and keyboard focus; the pressed glow is stronger. Intelligence icons and small corner stars sparkle during interaction alongside the existing shimmer. Decorative sparkles do not intercept taps or move controls; reduced motion keeps them static. Controls stay still, disabled actions do not glow, and reduced motion keeps the glow static. Dark cyan tints use bounded opacity to retain readable labels as depth increases. `public/ai-brand-model.js` is the shared allowlist for server rendering, settings previews, shell/frame updates and email colours. Settings remain company-scoped, revision-checked and protected by `ai.manage`; older clients preserve omitted palette/depth fields.
