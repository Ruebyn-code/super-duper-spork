# Permanent subpage navigation

Pages with several views use a permanent column on the left of the active content document. Ordering (including counts/history/transfers/stock/suppliers), Sales and expenses, Learning centre, Checklists, Rostering, Comms, Reporting, Administration, Settings and Labels use the same layout. Desktop/tablet show icons and labels; phones use a 44 px icon column with accessible names and tooltips. The global logo, search and account dropdown stay above the content, and phone main destinations remain in the bottom bar. The old top subpage bar is removed. Main navigation links open the feature directly, choosing an allowed destination for custom roles; subpages stay in the left column. The legacy destination elements remain hidden and inert for permission filtering and App edit identities.

`public/subpage-navigation-model.js` defines static page families, current routes and permission-aware links. `public/subpage-navigation.js` runs only in normal authenticated content frames, reusing native navigation elements and their listeners for dynamic feature views. Sales keeps its native expense links and adds its daily/hourly/projection destinations. Reporting derives views from the existing selector and follows its current capability restrictions. Labels keeps its real category buttons. Existing Library category controls and the Help category filter remain independent filters rather than new routes.

Native view controllers still own navigation, busy/draft guards, validation and active states. The Learning centre nav has a stable ID so selecting a page continues to update the actual moved controls. No clone handles operational writes. Changing a navigation view does not create assignments, checklist runs, clock punches, orders or paid intelligence requests. The existing persistent shell, Back/Forward, required reading, permissions and company/location/kiosk boundaries remain responsible for access.

The phone roster retains its modal above the underlying page. Its left subpage buttons update the existing section selector through its native change action; My/Team remain view options within Roster. Closing restores the original page. Expanded conversations, checklist/course readers and native dialogs retain their fullscreen/inert behavior. Print hides the subpage column.

Shared styling uses the `page-sidebar-*` classes and scoped theme-aware overrides in `public/subpage-navigation.css`. The column reserves content space and does not expand on hover, overlay fields or require a pin setting. Its own vertical scroll remains independent of page content. Only the content frame loads the new scripts; modal setup editors and the persistent parent do not create another bar. Keep saved App edit identities on native elements and never wrap the main content in `data-layout-ui`.

Verification: run `node --test subpage-navigation.test.js persistent-shell.test.js`, then `npm test`. Browser-check desktop/tablet/phone, keyboard/focus, hover width stability, native selected states, all page families, nested builders, modal/fullscreen modes, Back/Forward, dirty and in-flight saves, custom count/finance roles and an unlocked kiosk. Use isolated demo data, regenerate affected help scenes/media, and build/start the production image before pushing.
